# 임베딩 실행 방식 가이드

## 임베딩이 잘 되고 있는지 확인하는 방법

### 1. API로 상태/진행률 보기

**GET /admin/embedding/status** 를 주기적으로 호출하면 Chroma에 저장된 개수와 **진행 중인 배치 작업** 상태를 볼 수 있습니다.

- **진행 중일 때**: `progress.running === true`, `progress.processed`, `progress.total`, `progress.ok`, `progress.fail`, `progress.startedAt` 로 몇 건 처리했는지 확인 가능.
- **완료 후**: `progress.running === false`, 마지막 실행 결과가 `progress` 에 남음.
- **collection.count**: Chroma에 실제 저장된 임베딩 개수.
- **samples**: 저장된 샘플 메타데이터(확인용).

```bash
# 상태 조회 (배치 실행 중에는 몇 초마다 호출해서 진행률 확인)
curl -s http://localhost:8080/admin/embedding/status | jq .

# Chroma에 저장된 개수만 빠르게 보기
curl -s http://localhost:8080/admin/embedding/status | jq '.data.collection.count'
```

**임베딩 목록(일부) 조회**: `GET /admin/embedding/list?limit=100` — Chroma에 들어간 차량 목록·메타데이터 확인.

### 2. 서버 로그로 확인

전체/필터/증분 임베딩 실행 시 **50건마다** 다음 로그가 출력됩니다.

- `[embedding] 진행: N/M 건 (성공: O, 실패: F)`
- 시작/종료 시 `*** EMBEDDING JOB START *** total=...`, `*** EMBEDDING JOB DONE *** ok=... fail=...`

로그에 쿼리만 보이고 진행 로그가 안 보이면, 로그 레벨이 `com.carizon.rag` 에서 INFO 이상인지 확인하세요.

## 전체 임베딩 실행 vs 증분 임베딩 vs 배치 실행

### 1. 전체 임베딩 실행 (`embedAllCars`)

**용도**: 처음 시작하거나 전체 데이터를 다시 임베딩할 때

**동작 방식**:
- DB의 **모든 차량**을 조회
- 병렬 처리로 임베딩 생성 (6개 워커 스레드)
- 300건씩 DB에서 읽어서 처리
- 50건씩 묶어서 Chroma에 배치 저장

**특징**:
- ✅ 가장 완전한 임베딩 (모든 차량 포함)
- ❌ 시간이 오래 걸림 (수만 건이면 몇 시간 소요)
- ❌ 중간에 실패하면 처음부터 다시 시작해야 함
- ✅ 이미 저장된 것은 유지됨 (중복 저장 방지)

**사용 시나리오**:
- 초기 설정 시
- 데이터 구조가 크게 변경되었을 때
- 주기적으로 전체 재임베딩이 필요할 때

---

### 2. 증분 임베딩 실행 (`incrementalEmbed`)

**용도**: 최근에 업데이트된 차량만 임베딩 (일상적인 업데이트)

**동작 방식**:
- `car_master.updated_at >= since` 조건으로 **변경된 차량만** 조회
- 기본값: 최근 1시간 전 이후 업데이트된 차량
- 순차 처리 (병렬 처리 없음)
- 각 차량을 개별적으로 임베딩하고 저장

**특징**:
- ✅ 빠름 (변경된 것만 처리)
- ✅ 일상적인 업데이트에 적합
- ✅ 스케줄러로 자동 실행 가능
- ❌ 병렬 처리 없어서 대량 변경 시 느림

**사용 시나리오**:
- 매일 자동 실행 (스케줄러)
- 크롤링/머지 후 자동 실행
- 실시간 업데이트 필요 시

**예시**:
```bash
# 최근 1시간 전 이후 업데이트된 차량만 임베딩
POST /admin/embedding/incremental

# 특정 시간 이후 업데이트된 차량만 임베딩
POST /admin/embedding/incremental?since=2024-01-13T00:00:00
```

---

### 3. 범위 임베딩 실행 (`embedCarsInRange`)

**용도**: 특정 차량 ID 범위만 임베딩 (테스트/수동 보정용)

**동작 방식**:
- `fromCarId` ~ `toCarId` 범위의 차량만 조회
- 병렬 처리로 임베딩 생성
- 배치 단위로 Chroma에 저장

**특징**:
- ✅ 특정 범위만 선택적으로 처리
- ✅ 테스트나 디버깅에 유용
- ✅ 실패한 차량만 재처리할 때 사용

**사용 시나리오**:
- 특정 차량만 재임베딩 필요 시
- 테스트/디버깅
- 실패한 차량 범위만 재처리

**예시**:
```bash
# 차량 ID 1000~2000 범위만 임베딩
POST /admin/embedding/range?fromCarId=1000&toCarId=2000
```

---

### 4. 단일 차량 임베딩 (`embedCar`)

**용도**: 특정 차량 1건만 임베딩

**동작 방식**:
- 단일 차량 데이터 조회
- 임베딩 생성
- Chroma에 저장

**특징**:
- ✅ 가장 빠름 (1건만)
- ✅ 즉시 반영
- ✅ 테스트/수동 보정에 적합

**사용 시나리오**:
- 특정 차량만 수동으로 재임베딩
- 테스트
- 즉시 반영이 필요할 때

---

## 권장 사용 패턴

### 초기 설정
1. **전체 임베딩 실행** - 모든 차량 임베딩

### 일상적인 운영
1. **증분 임베딩** - 매일 자동 실행 (스케줄러)
   - 크롤링 → 머지 → 증분 임베딩 파이프라인

### 문제 발생 시
1. **범위 임베딩** - 실패한 범위만 재처리
2. **단일 차량 임베딩** - 특정 차량만 수동 보정

---

## 성능 비교

| 방식 | 처리 속도 | 메모리 사용 | 적합한 상황 |
|------|----------|------------|------------|
| 전체 임베딩 | 느림 (수 시간) | 높음 | 초기 설정, 전체 재처리 |
| 증분 임베딩 | 빠름 (수 분~수십 분) | 낮음 | 일상 업데이트 |
| 범위 임베딩 | 중간 | 중간 | 선택적 처리 |
| 단일 임베딩 | 매우 빠름 (초 단위) | 매우 낮음 | 수동 보정 |

---

## 주의사항

1. **전체 임베딩은 시간이 오래 걸립니다**
   - 수만 건이면 몇 시간 소요
   - 서버 리소스를 많이 사용

2. **증분 임베딩은 자동화 권장**
   - 스케줄러로 매일 실행
   - 크롤링/머지 후 자동 실행

3. **Chroma 서비스가 실행 중이어야 함**
   - Chroma가 없으면 모든 임베딩 작업 실패
   - `docker run -p 8000:8000 chromadb/chroma`

4. **임베딩 서비스(Ollama/HuggingFace)가 실행 중이어야 함**
   - Ollama: `ollama serve`
   - HuggingFace: API 키 필요
